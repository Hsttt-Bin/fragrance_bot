# 接入真实 RAG 检索（暂不接 LLM）

## 目标 / 背景

把 `/api/chat/stream` 的假数据替换为真实混合检索结果（向量召回 + BM25 + query 改写 + RRF 融合 + rerank 精排），content 事件暂以占位文本占位，不接 LLM 生成。

## 改动范围

- `website/backend/chat.py`：
  - 顶部 `sys.path` 指向项目根，使 `knowledge_base` 包可被导入（它是相对导入包）。
  - 新增 `init_retriever()`；接口内用 `asyncio.to_thread(retriever.search, question)` 把阻塞检索放进线程池。
  - `retrieval` 事件输出改写后的 query 列表 + 各命中块向量分 / BM25 分；`sources` 事件输出命中块原文与得分；`content` 为占位文本。
  - 附带临时观测 print（`flush=True`），用于确认改写 / 精排链路真实执行（暂保留）。
- `website/backend/main.py`：用 `lifespan` 在启动时初始化一次 `HybridRetriever` 并存入 `app.state`，进程内复用，避免每次请求重载 FAISS。
- backend `.venv` 补装 `faiss-cpu` / `numpy` / `jieba` / `httpx`。
- 未改动 `knowledge_base/` 下任何文件（导入只读）。

## 验收标准

- 真实 query 实测：`retrieval` 返回改写 query 与向量 / BM25 分，`sources` 返回命中块原文 + 得分，`content` 为占位，`done` 收尾。
- 确认改写（返回 3 条改写 query）与精排（`rerank_score` 非零）均真实执行。
