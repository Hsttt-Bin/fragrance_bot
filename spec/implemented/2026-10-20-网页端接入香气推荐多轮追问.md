# 网页端接入香气推荐（多轮追问）

## 目标 / 背景

网页端问「我是金牛座，想用在睡觉前，有没有什么推荐的香气」，答案退化成了通用 RAG 回答（「星座这个我不太确定」）。根因：香气推荐前置分流（`knowledge_base/recommender.py`）只接在了命令行入口 `search.py`，网页后端 `chat.py` 从未调用它。本步把推荐分流补进网页端，并支持多轮追问（维度不足时先问，用户补全后出推荐）。

## 改动范围

- `website/backend/chat.py`：
  - `ChatRequest` 新增可选字段 `session_id`（默认空，向后兼容旧请求）。
  - 新增内存会话状态 `_sessions` / `_get_session` / `_new_session` / `_clear_session`，按 `session_id` 记忆推荐追问上下文（上限 500 条，超限淘汰最早）。
  - `_stream` 在检索前加推荐分流，逻辑对齐 `search.py` 交互模式：`is_recommend_intent` / `extract_dims` / `merge_dims` 判断；维度 ≥2 或已追问一轮 → `recommend()` 出推荐（失败降级回 RAG）；维度不足 → `build_followup()` 追问并保留会话。
- `website/js/chat.js`：页面加载时生成 `SESSION_ID`，随请求体一并发送，用于多轮追问上下文。
- 未改动 `knowledge_base/` 下任何文件。

## 验收标准

- 「我是金牛座，想用在睡觉前，有没有什么推荐的香气」→ 命中推荐，返回基于 `scents.json` 的个性化推荐（星座+场景理由、价位），而非「星座这个我不太确定」。
- 「我是金牛座」→ 追问「想放在什么场景用呢…」；同一 `session_id` 下一句「睡前用」→ 出推荐。
- 普通问题（如「蜡烛烧出洞怎么办」）仍走 RAG 链路（retrieval → sources → 流式 content → done），不受影响。
